## 計測の読み方

既定は有効。起動ウィンドウに `[移動計測]` に続くJSONを1イベント1行で出します。ゲーム内チャットへは送りません。

| event | 内容 |
|---|---|
| `sample` | 歩行中5tickごとの送信位置、入力、目標、ダッシュ、足元・体・頭の地形、権威位置の受信時刻、古さ |
| `authority` | 権威位置の受信。補正は全件記録。`server_post_move` は全件集計しログのみ歩行中5tickに1回 |
| `move_start` / `move_summary` | goto単位の開始と終了。長距離移動・再計画の内部呼び出しは外側の1回へ集約 |
| `terrain_error` | decode失敗と未知ブロックID例外の累計 |
| `session_end` | 終了時の地形カウンタ |

- 送信位置は直近40tickの固定長履歴に保存。`t` はプロセス内の単調増加時刻（ms）で、暦の日時ではありません。
- `localTick` は計測側の送信回数。`authInputTick` は実パケットのtickを文字列化したものです。両者を混同しません。
- 位置は原則パケットの目線座標。`target` は既存gotoと同じ足座標。地形サンプルは目線座標から1.62を引いて読み取ります。
- `driftNow` は最新送信位置との水平距離。`bestLagTicks` は0〜10tickの候補中で距離が最小のもの、`driftAtBestLag` はその距離です。
- **ラグは軌跡の一致からの推定であり、実測RTTではありません。** `server_post_move` にはサーバーtickが無いため、ネットワーク遅延やサーバーでの処理時刻を確定できません。停止や往復で候補が同距離なら `ambiguous:true` です。
- `ageMs` は直前の `server_post_move` 受信からの経過時間。未受信ならnull、200ms超または未受信なら `stale:true`。post受信イベント自体では0になり、前回との間隔は `previousPostAgeMs` に残ります。
- `historyAgeMs` / `historyStale` は比較に使う最新送信履歴の古さ。欠落したtickを隣の履歴で代用しません。
- 補正は受信パケットのtickと完全一致する履歴で比較。`horizontalError` / `verticalError` に出します。履歴に無ければ `matched:false`、誤差nullです。
- 補正・テレポート・復活・ディメンション変更後20tickは `suppressed:true`。復活等では履歴をクリアし、補正後は以前の軌跡をラグ候補から外します。
- `move_summary` の平均・最大・ラグ中央値は、抑制中／古い履歴／履歴なしを除外したpost受信サンプルのみ。`samples:0` なら値はnullです。ゼロ誤差と読み替えないでください。曖昧な候補の件数も出します。
- `steps` は前進入力回数、`inputs` は静止を含む入力回数です。到着成功を意味しません。成功・失敗は従来の制御処理が判定します。
- `terrainCounters.updateSubchunkBlocks` は受信件数のみ。パケットの地形反映はまだ追加していません。`collision.stats` は手順6の組み込み後に追加する対象です。
- `[移動方式]` は開始時も出力します。`authority:null` / `authorityPacketReceived:false` は方式の通知がまだないという意味であり、サーバー権威方式だと断定しません。後から届く既存の方式ログも一緒に保存してください。

## 手順4：ユーザーによる実Realmでの採取

1. 既存BotをCtrl+Cで終了し、`RealmsAI起動.bat` を1つだけ起動し直します。Realmの再起動は不要です。
2. 比較用の安全な試験場を決めます。平地20×20、ツタ付き原木、階段・スラブ・フェンス・カーペットを用意します。
3. 次の試験を行い、試験開始・終了の位置と成功／失敗をメモします。移動できなくても、途中で地形判定コードや速度を変更せず失敗ログを残します。

| 試験 | 回数 | 記録 |
|---|---|---|
| 平地20ブロック移動 | 5回 | 到着結果、補正数、所要時間、計測ログ |
| ツタ付き原木のそばで伐採 | 1〜3回 | 接触・登攀・停止の有無と計測ログ |
| 階段・スラブ・フェンス・カーペットを含む往復 | 各1回以上 | 通行結果、補正位置とブロック名 |

4. 起動時の `[移動方式]`、各試験の `[移動計測]` と `[移動診断:結果]`、失敗メッセージを共有してください。**認証コード・トークンは除外**します。
5. このログを判定してから、WP1aやWP2への着手を決めます。

計測は既定で有効です。明示的に有効にして起動する場合：

```powershell
$env:TAKEN_TELEMETRY='1'
& 'C:\mc-server\AI\aibot-realms\RealmsAI起動.bat'
```

一時的に無効化する場合は同じPowerShellで次を実行して起動し直します（.envや認証ファイルの変更は不要）：

```powershell
$env:TAKEN_TELEMETRY='0'
& 'C:\mc-server\AI\aibot-realms\RealmsAI起動.bat'
```

## 検証の限界

模擬テストは実Realmでの成功を保証しません。実地形での挙動、通信遅延分布、計測出力によるFPS・処理負荷、方式通知と地形更新パケットの実際の頻度は未検証です。
