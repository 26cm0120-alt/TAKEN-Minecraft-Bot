# フォルダ再編の指示書（TAKEN-Minecraft-Bot）

## 目的

ルートに121ファイルが平置きで見づらいため、本体・テスト・ドキュメントをフォルダに分ける。
**これはファイルの移動と参照パスの修正だけの作業であり、コードのロジックは一切変更しない。**

## 目標の構成

```
（ルートに残す）
package.json / package-lock.json / run-tests.js（手順4で改修）
.env.example / .gitignore
README.md / AGENTS.md / TAKEN_REVIEW_FOR_CODEX.md / AI_REVIEW_HANDOFF.md
RealmsAI起動.bat / Realms接続確認.bat / 招待を承諾.bat（手順4でパス修正）
start-local-ai.ps1（無変更）
auth/（実行時に作られるフォルダ。git対象外。そのまま残す）

src/    … 本体の .js 全部と minecraft-dictionary.json
tests/  … *.test.js 全部
docs/   … 使い方・手順のドキュメント（手順2の対象）
```

## 手順0：事前確認（ベースライン）

1. `git pull` で最新化し、`git status` がクリーンなことを確認する。
2. **移動する前に** `npm test` を実行し、成功件数（2026-11-26時点では313件）を記録する。これが再編後の比較基準になる。
3. ベースラインで失敗がある場合は、移動を始めずに報告する。

## 手順1：本体を src/ へ

- ルートの `.js` ファイルのうち、`*.test.js` と `run-tests.js` を除く全てを `git mv` で `src/` へ移動する。
- `minecraft-dictionary.json` も `src/` へ移動する。
  - 理由：`item-dictionary.js` が `new URL('./minecraft-dictionary.json', import.meta.url)` で自分の隣から読むため、必ず一緒に移動する。
- 本体どうしの import（`from './○○.js'`）は、同じフォルダ内なので**変更不要**。

## 手順2：テストを tests/ へ、ドキュメントを docs/ へ

- `*.test.js` の全てを `git mv` で `tests/` へ移動する。
- 次のドキュメントを `git mv` で `docs/` へ移動する：
  - AIの使い方.md / 準備手順.md / WP0-計測とベースライン採取.md
  - クラフトと道具作成の使い方.md / 拡張機能の使い方.md / 死亡と復活の確認.md
  - 自動防衛と食事の使い方.md / 落下アイテム回収の使い方.md
  - taken-bot-codex-plan-2026-11-18.md
- README.md / AGENTS.md / TAKEN_REVIEW_FOR_CODEX.md / AI_REVIEW_HANDOFF.md は**ルートに残す**（AGENTS.mdと正本計画はルートが前提のため）。

## 手順3：参照パスの修正

1. **tests/ の import**：テストファイル内の本体への import を `./○○.js` → `../src/○○.js` に書き換える。テストどうしの import（あれば）は `./` のまま。
2. **run-tests.js**：テストの読み取り先をルート直下から `tests/` フォルダに変更する（`node --test` へ渡すパスも `tests/` 配下になるよう直す）。ファイル自体はルートに残す。
3. **package.json**：`"start": "node --env-file=.env src/index.js"` に変更する。`"test"` は変更しない。
4. **.bat の修正**：
   - RealmsAI起動.bat / Realms接続確認.bat：`index.js` → `src/index.js`
   - 招待を承諾.bat：`accept-invite.js` → `src/accept-invite.js`
   - start-local-ai.ps1 は .js を参照していないので**無変更**。
5. **src/index.js の auth パス**：`new URL('./auth/', import.meta.url)` を `new URL('../auth/', import.meta.url)` に変更する。
   - 理由：authキャッシュの場所を今までどおりルートの `auth/` に保ち、再ログインを発生させないため。**auth/ の中身には触らないこと。**
6. **文書のリンク・パス**：README.md 内のドキュメントリンク（準備手順.md、AIの使い方.md、WP0-計測とベースライン採取.md）を `docs/…` に書き換える。AGENTS.md と TAKEN_REVIEW_FOR_CODEX.md にルート前提のファイルパスがあれば `src/` `tests/` `docs/` 前提に直す。

## 手順4：漏れの洗い出し（grep）

移動と修正が終わったら、次を全ファイルで検索し、ルート前提の参照が残っていないか確認する。残っていれば手順3と同じ規則で直す。

- `new URL(` … import.meta.url 基準のファイル読み込み（辞書と auth 以外にもあるかもしれない）
- `readFileSync` / `writeFileSync` … 相対パスでファイルを読む・書く箇所
- `from './` … import の残り（src/ 内は正常、tests/ 内は手順3-1どおりになっているか）
- `node ` を含む行（.bat / .ps1 / .md 内の起動コマンド）

## 手順5：検証

1. `npm test` を実行し、**手順0のベースラインと件数が一致し、全件成功**することを確認する。
2. RealmsAI起動.bat から Bot を起動し、Realmへ接続して通常どおり応答することを確認する。接続確認ができない環境では、無理に進めず「実Realm未確認」と報告に明記する（テスト合格＝完了ではない、という AGENTS.md のルールどおり）。
3. `git status` で、移動が rename として認識されている（履歴が切れていない）ことを確認する。

## 手順6：コミットと push

- 1コミットにまとめる。メッセージ：`Reorganize files into src, tests, and docs folders`
- push まで行い、コミットSHAを報告する。

## 報告の形式

- テスト件数：再編前 ○件 → 再編後 ○件（全件成功かどうか）

- 引っかかった点・想定外の参照があれば、その内容
- コミットSHA

## 禁止事項（AGENTS.mdの絶対ルールの再掲）

- `.env` 本体と `auth/` の中身を読まない・書かない・共有しない（手順3-5のパス文字列の変更は除く）。
- コードのロジックを変更しない。移動と参照パスの修正のみ。
- ゲート条件（完了条件を満たしたかどうか）を自分で判断して次へ進まない。
- 変更のたびにテストを実行する（この作業では手順0と手順5）。
